# Native boundary notes

The authoritative shared contract is `../../docs/CLIENT-API.md` and host `protocol.ts`. Native DTOs mirror JSON field names; missing nullable layouts use defaults. Snapshot/navigation data is observed state, not execution authority.

## Current implementation decisions

- Host transport: HTTPS origin only, exact SHA-256 certificate pin from trusted setup, no redirects, bounded timeouts. Pair code exchange does not bootstrap trust. Android tokens/pins are protected by app-private AES-GCM ciphertext with a non-exportable Keystore key.
- Wire serializer: Unity's supported Newtonsoft JSON package; null records stay null. Optional `Message.origin` is a typed `DelegationOrigin` with kind, parent conversation, nullable parent task and coordinator parent run; absent origin remains absent on serialization. Delegated initial instructions retain that provenance in snapshot/history/transcript, but are neither reply previews nor automatic spoken replies. Real owner messages keep their role and preview behavior. Polymorphic `$type` handling is off and metadata is ignored. JSON values never invoke owner navigation, grant changes or new receiver selection.
- Focus: receiver = deliberately selected task's conversation, otherwise entered space conversation. Missing selected task yields unavailable receiver, not a silent fallback. Application-view selection never creates a per-app agent.
- Voice: native microphone permission follows explicit enable; local turn onset copies receiver. Owner/session/connection/output gates suppress capture. A plain `VoiceTurnDetector` consumes PCM samples: amplitude ≥0.015 starts hands-free capture, 12,800 quiet samples (0.8 seconds) or 400,000 total samples (25 seconds) finish it. `VoiceSession` still owns microphone/permission IO and actual `Finish`/`Submit`; submission needs at least 3,200 samples and uses the onset receiver. Sample time, not frame time, drives these rules. Provider/transcription/generation live on host. Text and speech return retained acknowledgment identities, not a claimed execution result.
- Navigation: opening global Inbox is local. Jumps check current request version and destination, preserve first origin, and change receiver deliberately. Return validates the retained destination; Parent Back never consumes that return point. Owner text recognizes the exact explicit global-Inbox phrase. Voice navigation requires a `/v1/voice` acknowledgment with the captured identity, trusted owner `transcript` and `state='local-command'`, after the host has intercepted it without dispatching execution; this contract capability must be present to call global voice navigation verified. Agent/content text never opens Inbox.
- Effects: native is not an environment confinement boundary. It sends task/environment/view/generation/lease identities; host authenticates caller and coordinator/environment enforce current authority. No native shell, broad desktop connection or simulated-agent fallback exists.
- Takeover: owner must see and confirm any workload reset warning for take or resume; no automatic restart for handoff or uncertainty. `handoff` details beginning `confirmation-required:` (or the explicit restart-confirmation phrase) expose a separate confirmation dialog. Until host returns an acknowledged owner lease matching the displayed frame epoch, input stays disabled. Before an ordinary control request, `GET /v1/tasks/:id/control` supplies the actual lease even without usable frames. Missing, wrong-task, unsupported-owner or zero-epoch leases block the transition. Confirm restart retains the exact warning epoch; it never substitutes a freshly read epoch for a previously confirmed warning. The read lease is not an input acknowledgement.
- Organization: project-root edits use the project route; children move only to observed same-project parents outside their own descendants. Space links do not grant context access. Node positions and task layouts persist through their existing host routes. Sources come from real uploaded metadata/content and retain their source space, provenance and hash; the client never reads arbitrary host paths.
- Inbox: open and deferred requests remain visible/jumpable against current request IDs/versions. Closed requests retain read-only full evidence and owner disposition. Complete evidence uses retained-detail pagination (including newline-heavy content); Decision appears only on the last page, with a route back to full evidence. Superseded reviews retain the old attempt pin and obsolete reason. Explicit Dismiss requires a reason and closes only the request, never authority, execution or reservations. Existing-authority confirmation takes a receipt ID and exact version in separate typed fields after the documented CLI/private-binding handoff; no text answer is a grant. Answer feedback tells the owner to jump and send a follow-up because no new execution starts.
- Owner dialogs: background snapshots redraw observed context without removing explicit restart warnings/details. Identical content/status does not continuously rebuild the scene. Chained text fields close the previous platform keyboard before opening the next.
- Input: the global Inbox shortcut binds only the left app-menu control and has a keyboard F1 alternative. Mouse/touch selects native world targets through the app camera; neither shortcut intercepts the headset's right system button.
- Persistence: host owns projects, spaces, layouts, full messages, requests and work identities. Client stores its selected space/task/view and Inbox origin privately by IDs, without persisting transcripts/audio in navigation settings. Changing HTTPS origin, pin or paired client credentials, or removing pairing, clears host-bound snapshots/revision, navigation/origin, history, reply/placement caches, frames/leases, dialogs and pending retries. Connection epochs fence late pairing/snapshot/request callbacks; old UI operations are cancelled. Same-identity reconnect retains monotonic revision checks. Existing `VoiceSession.SetConnected(false)` discards captured input/output without clearing microphone permission or enable preferences. No host/product record or grant is deleted.

## Validation limits

A batch build and automated state/UI tests do not establish wearable comfort, true hands/controller behavior, actual TLS/Keystore behavior on Quest, speech quality, environment safety, real agents or 30-minute native frame-time targets. Missing provider/login/permission/activation/device evidence stays blocked at the full Manifest level. The client cannot broaden those prerequisites to obtain a passing result.
